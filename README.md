# Импорт персонажей для Virtual TTG

Внешний модуль [Virtual TTG](https://github.com/TTG-Club/vttg): переносит
персонажа с листа [TTG Club](https://ttg.club) прямо в мир — вместе с классом,
видом, предысторией, владениями, чертами и инвентарём.

Работает с файлом, который отдаёт кнопка **«Экспорт»** на листе персонажа
(`.json`). Собранный актёр появляется в списке персонажей мира.

## Что импортируется

| С листа персонажа | Во что превращается | Примечание |
|---|---|---|
| имя, аватар | имя и аватар актёра | аватар остаётся ссылкой на сайт |
| `abilities` | `system.abilities` | как есть, без пересчёта |
| `characterClass` + `additionalClasses` | `system.classes` | ключ берётся из ссылки: `fighter-phb` → `fighter` |
| `health.levelGains` | `classes[].hitPointsGained` | модификатор Телосложения вычитается — система добавит его сама |
| `hitDice` | `classes[].hitDiceUsed` | сколько костей уже потрачено |
| `species`, `size` | `system.species` | происхождение (lineage) переносится только названием вида |
| `characterBackground` | `system.background` | вместе с повышениями характеристик и чертой происхождения |
| `skills`, `savingThrows`, `proficiencies` | `system.proficiencies` | навыки без владения не переносятся: для системы это одно и то же |
| `armorClass` | `system.armorClass` | КД считает система по надетому доспеху; ручной и природный КД переносятся как есть |
| `health`, `speed`, `vision` | хиты, передвижение, зрение токена | тёмное зрение уходит в настройки токена |
| `currency` | `system.currency` | медь/серебро/электрум/золото/платина |
| `classResources` | `system.classCounters` | владельцем счётчика становится основной класс |
| `features` | `actor.features` | разметка сайта (`{@glossary …}`) разворачивается в markdown |
| `inventory` | `actor.equipment` | оружие с формулой урона, доспех с КД и лимитом Ловкости, магические бонусы — активными эффектами предмета |
| `personality` | описание актёра | мировоззрение, возраст, внешность |

### Что НЕ переносится

Мастер импорта показывает это списком до создания актёра:

- **Заклинания.** Их механику (школа, время, компоненты, области) лист не
  описывает — добавьте заклинания персонажу из компендиума мира.
- **Истощение.** Это состояние, а не поле листа — наложите его на сцене.
- **Заметки листа.** Формат заметок на сайте свой.
- **Бонусы предметов, которых нет среди эффектов системы** — такие предметы
  перечислены в предупреждении поимённо.

## Установка

```bash
pnpm install
pnpm build
node scripts/installToWorld.mjs "D:/путь/к/папке/мира"
```

Модуль попадёт в `<папка мира>/modules/character-import/`. Дальше в мире:
настройки → «Управление модулями» → «Перезагрузить мир». В левом тулбаре сцены
появится кнопка импорта.

## Требования к хосту

Модулю нужно разрешение `actor-write` — оно появилось в API хоста вместе с этим
модулем. Хост должен уметь:

- `api.actors.create` / `api.actors.update`
- `api.system.getActiveSystemId` (модуль проверяет, что мир на `dnd5e-2024`)

Полный контракт — в `docs/MODULES.md` репозитория хоста. Права проверяет сервер:
создать персонажа может тот, у кого в мире есть право `CREATE_ACTORS` (у игроков
оно обычно есть), а правит актёра мастер или его владелец.

Модуль объявлен совместимым только с системой **`dnd5e-2024`**: форму актёра
задаёт она, и в мире на другой системе модуль не появится вовсе.

## Разработка

```bash
pnpm dev            # пересборка при изменениях
pnpm type-check     # проверка типов
pnpm test           # тесты парсера и конвертера
```

Сборка — IIFE (`dist/client.js` + `dist/styles.css`): хост грузит модуль обычным
`<script>`, а Vue берётся из `globalThis.Vue` хоста, чтобы компоненты работали на
том же экземпляре Vue, что и приложение.

Структура:

```
src/
├── main.ts               регистрация модуля, кнопка в тулбаре
├── types/vttg.ts         типы хостового API (копия контракта из docs/MODULES.md)
├── types/dnd5e.ts        целевая форма актёра системы dnd5e-2024
├── sheet/schema.ts       zod-схема листа персонажа
├── sheet/parse.ts        чтение файла и сводка
├── sheet/richText.ts     разметка сайта и узлы редактора → markdown
├── convert/              маппинг листа в актёра (классы, владения, черты, инвентарь)
├── import/runImport.ts   сценарий импорта целиком
└── ui/                   мастер импорта и кнопка тулбара
```

`fixtures/dwarf-fighter.json` — настоящий экспорт листа (дварф-воин 1 уровня с
магическим предметом и счётчиком ресурса). На нём держатся тесты конвертера.

## Тонкости формата

- **Ключи контента.** Лист опознаёт контент ссылками сайта (`dwarf-phb`,
  `item:greatsword-phb`), система — короткими ключами (`dwarf`, `greatsword`).
  Модуль снимает префикс типа и хвост источника; сам источник (`phb`, `dmg`)
  при этом не теряется — он остаётся в идентификаторе предмета.
- **Хиты за уровень.** Лист хранит ИТОГОВУЮ прибавку (вместе с модификатором
  Телосложения), система — «чистый» бросок. Модификатор вычитается при импорте,
  иначе после первого же пересчёта максимум хитов подскочил бы.
- **Урон оружия.** В формулу не попадает модификатор характеристики
  (`2к6`, а не `2к6+3`): систему он интересует отдельно, иначе бонус учёлся бы
  дважды. Кубики пишутся по-русски (`к`), как во всём контенте системы.
- **Магические бонусы.** Бонус предмета (`Сила 19` у рукавиц силы огра)
  становится активным эффектом предмета с `transfer: true` — он включается,
  когда предмет надет, и выключается, когда снят.
